📌 The rule

  1. Read this file before starting any non-trivial Volt work — regardless of which session, machine, or person is doing the work. Don't assume you're continuing from a prior conversation; assume real work happened that you haven't seen.

Volt is an in-house AI marketing suite built for SME South Africa (smesouthafrica.co.za) — copy generation, canvas graphic design, short-form video editing, a newsletter builder, and performance analytics, all sharing one Brand Kit and one backend.

API surface

4 functions stay top-level (hot/heavy paths get their own cold-start budget): generate.js, transcribe.js, postiz.js, projects.js.

Everything else dispatches through one catch-all, api/[...volt].js, to handlers in api/_routes/: kit, image, upload, scrape, assets, billing, paystack, brain, instagram, facebook, tiktok, mcp. Public URLs are unchanged either way (/api/kit etc.) — this exists only to stay under Vercel Hobby's 12-function cap.

MCP server LIVE: generate-only

api/_routes/mcp.js (/api/mcp) — lets any MCP-compatible AI tool (Claude Desktop, Claude Code, …) connect to Volt over MCP's Streamable HTTP transport and call three tools: get_brand_kit, generate_ad_copy, generate_email_copy. Reuses generate.js's own prompt builders/system prompts (now named exports, alongside its default handler) rather than forking a second copy — one place for that logic to drift. Auth is a separate personal API key (sql/api_key.sql, SHA-256 hash stored, raw value shown once at creation) because an MCP client can't do a browser OAuth dance against Supabase the way every other Volt page does; one active key per account, minted/rotated/revoked from Admin → AI Tools (MCP). See SETUP-MCP.md.

Deliberately generate-only — no tool can publish anything or change a setting; a connected AI tool can draft content, never act live on Joel's behalf. Studio design-image generation is NOT exposed, and that's architectural, not a scope choice: studio-engine.js draws on an OffscreenCanvas inside a browser Worker, so there's no server-side renderer an MCP tool call could invoke — offering it would need a real headless-rendering service (node-canvas or a headless browser), a separate, larger build, not a new route.

Direct social publishing LIVE: Instagram + Facebook TikTok: private-only, pending TikTok's review

Bypasses Postiz entirely for three platforms — Volt calls each platform's own API directly, so a failure surfaces that platform's own error text instead of a third party's opinion of it. All three share the Schedule page's queue/calendar UI (ig_queue / fb_queue / tiktok_queue, same atomic-claim-then-publish pattern, same GitHub Actions drain every 5 minutes — Vercel Hobby cron is once/day and can't honour a real posting time).

Instagram + Facebook (api/_routes/instagram.js, api/_routes/facebook.js) share ONE Meta connection/token (one more scope, pages_manage_posts, unlocks Facebook on top of Instagram) — set up by pasting a token in Admin → Connections, see SETUP-INSTAGRAM.md. Instagram does stories/feed/reels via the media-container-then-poll flow; Facebook does feed/photo posts (single synchronous call) and now real Page Stories (/photo_stories, unpublished-photo-then-publish, two calls) — Facebook Reels are NOT implemented (would need a chunked video upload, a materially bigger job) and are refused with a clear error rather than silently posting the wrong type.

TikTok (api/_routes/tiktok.js) is a genuinely separate integration — its own OAuth 2.0 flow (Volt is the OAuth client; no Graph-Explorer-style token-paste option exists for TikTok), its own credential row, own queue table. Publishes via PULL_FROM_URL (TikTok fetches the video Volt already hosts — no chunked byte upload through a serverless function). Every post is forced private (SELF_ONLY) until TikTok approves the app's video.publish scope for production — a normal, bounded 2–4 week review every third-party poster goes through, not a Volt limitation; Admin's TikTok card and the Schedule chip both say "private only" until it clears, and nothing about the code changes when it does. TikTok's refresh_token ROTATES on every use — ensureFreshToken() always overwrites both stored tokens; assuming the old refresh_token still works is the one way to silently break this later. See SETUP-TIKTOK.md for the one-time app registration.

Both "Post now" flows write a status:'done' queue row immediately (not just scheduled-then-drained posts) — this was a real gap fixed 2026-08-21: an immediate publish used to leave zero trace in Volt's own tables, so it could publish successfully and never appear on the Schedule calendar.

Gotcha FIXED 2026-08-13, commit 31a97a5

The router used to read the endpoint name from req.query.volt (the catch-all param). Vercel does not reliably populate that for plain Node functions — in production it arrived empty, so every routed endpoint 404'd ("Unknown endpoint") until someone hit one. Fixed to derive the name from the URL path instead; param kept only as a fast path. If this class of bug ever resurfaces, check endpointName() in api/[...volt].js first.

Auth is a real Supabase session (requireSession in api/_guard.js), fail-closed (503) if Supabase env vars are missing. The old public x-app-key/APP_KEY path is retired dead code — do not tell anyone to send that header; several stale docs (old CLAUDE.md, this repo's own README) still say to, and they're wrong.

Hard rules that are still true

  • No paid services. Volt runs on free-tier APIs only (free Gemini model, not Imagen/OpenAI). Flag it and offer a free alternative if a feature would need a paid one.
  • Push to live by default. Joel wants changes committed and pushed to main (Vercel prod); he QCs from the live app, not a preview branch.
  • webSecurity is ON in the desktop shell. Any new external image load MUST go through window.voltAsset(url) (routes via /api/scrape?img=1 so bytes arrive same-origin) or canvas export will taint/fail.
  • Email typography must be inline, not stylesheet-only. Any new email body section is either fully inline-styled or bare <p>/<h2> (which inlineBaseTypography() in email-blocks.js will normalise) — Outlook and several ESPs ignore or strip a <style> block. Never hand-write a font-family fallback chain; use the shared FAM_HEAD/FAM_BODY constants.
  • New API endpoints go in api/_routes/ + the router's ROUTES map, never as a new top-level file (the 12-function cap).
